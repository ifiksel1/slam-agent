**`photo_scale` = 1.0e-9, NOT 0.01.** The photometric Jacobian (dI/du·du/dp) is O(1e3) vs geometric O(1); in the information form `HTH = Σ w·hᵀh` it must be ~1e-9 to balance geometric, else it dominates and diverges. Apartment sweep: **1e-6 → NaN; 1e-9 → stable (loop 0.004m, max-step 0.058m ≈ geo 0.003/0.059); 1e-12 → stable but neutral.** Photometric is neutral-and-stable where geometry is healthy (apartment) = intended; the real benefit needs a DEGENERATE scene. Guards that matter: finite-check each photometric row, splat skips non-finite (NaN) points, FeatureManager skips candidates with no real point, ImageProcessor skips erosion when `erosion_margin<=0`. **YAML floats need `1.0e-9` form (`1e-9` parses as a STRING → param-type throw).**

**Hard-won gotchas (cost hours):**
- **Zombie nodes poison everything.** `ROS_DOMAIN_ID=0` + duplicate component-container name `ellipselio_container` → stale 30-min-old nodes kept answering param queries and competing on topics, corrupting every A/B. `kill -9` leaves stale DDS discovery. FIX: `docker restart coinlio_fusion` before each run for a clean DDS slate; verify `ros2 node list` empty.
- **`pkill -f <pattern>` self-matches** the script's own command line (the pattern text is in argv) → exit 137 self-kill. Kill by PID via `ps -eo pid,comm | awk`, never `pkill -f` on words that appear in the script.
- **Component-node stdout is lost on `kill -9`** (block-buffered) and `stdbuf` doesn't reach the grandchild container → RCLCPP_INFO/`[photometric] enabled` never lands in the log. To prove code ran, write to a file (`fopen`/`fflush`) — capture-independent.
- EllipseLIO declares every param explicitly (no auto-declare) → new `photometric.*` params must be `declare_parameter`'d or YAML silently falls back to defaults (`ros2 param get` → "not set"). With `use_sim_time:=true` the node's timer (and thus `InitPhotometric`) only fires once the bag publishes `/clock`.
- `ros2 launch` with bag rate ≥2–3 can starve `SyncPackages` (no IEKF updates). Use rate 1.0 for correctness runs.
